## 4. 项目结构问题

| 问题 | 严重度 | 建议 |
|------|--------|------|
| 双 lockfile (`pnpm-lock.yaml` + `bun.lock`) | 🔴 高 | `pnpm-lock.yaml` 被 git 追踪，`bun.lock` 是未追踪的本地文件。不同开发者可能使用不同包管理器导致依赖版本不一致。建议：锁定一个包管理器，将另一个 lockfile 加入 `.gitignore` |
| `site` URL 缺失 | 🔴 高 | `astro.config.mjs` 未配置 `site` —— 导致 sitemap 无法生成正确的绝对 URL、canonical URL 回退到相对路径、RSS feed 缺少 base URL |
| 无 CI/CD 配置 | 🟡 中 | 未发现 `netlify.toml`、`vercel.json`、`wrangler.toml` 或 `.github/workflows/`，部署流程依赖手动操作 |
| 构建并发度为 1 | 🟡 中 | astro 内部配置显示 `build.concurrency: 1`，多核构建潜力未被利用 |
| `dist/` 目录为空 | 🟡 中 | 可能长期未执行构建，或上次构建后被清理（`.gitignore` 已排除） |
| `devDependencies` 为空 | 🟢 低 | `package.json` 的 `devDependencies` 为 `{}`，所有依赖放入 `dependencies`。对 SSG 项目虽无运行时影响，但语义上 `astro`、`@tailwindcss/vite` 等应归入 devDependencies |
| `scripts/` 缺少依赖声明 | 🟢 低 | `migrate_hugo_content.py` 无 `requirements.txt` 配套说明其 Python 依赖 |
| `agent_memory/` 未在 `.gitignore` | 🟢 低 | 代理记忆文件被 git 追踪，当前内容为经验教训总结，无敏感数据 |
